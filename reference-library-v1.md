# Reference Library --- первая версия

## 1. Цель

Сделать минимальную локальную библиотеку референсов для изображений и
видео, которая:

-   работает с уже существующей папкой с референсами;
-   не требует переноса файлов в базу данных;
-   не использует SQLite или другую БД;
-   хранит метаданные рядом с каждым ассетом в sidecar-файле;
-   позволяет открыть библиотеку в браузере через локальное приложение;
-   позволяет просматривать, размечать тегами и фильтровать существующие
    референсы;
-   не привязывает данные к конкретной установке приложения.

Основной принцип:

> **Library --- источник истины. Application только читает и изменяет
> Library. Любые производные данные должны быть восстанавливаемыми.**

------------------------------------------------------------------------

## 2. Разделение Application и Library

Приложение и пользовательские данные существуют независимо.

Пример:

``` text
ReferenceApp/
├── backend/
├── frontend/
└── ...

D:/GoogleDrive/References/
├── .library/
│   ├── config.json
│   └── tags.json
├── folder-a/
│   ├── image01.jpg
│   ├── image01.jpg.meta.json
│   └── video01.mp4
└── folder-b/
    └── image02.png
```

Приложение должно уметь подключаться к произвольной папке Library.

Путь к последней открытой Library является настройкой конкретной
установки приложения и **не хранится внутри Library**.

------------------------------------------------------------------------

## 3. Текущая библиотека

Первая версия должна работать с существующей папкой файлов без
предварительной миграции.

При подключении Library приложение рекурсивно сканирует все вложенные
папки и ищет поддерживаемые изображения и видео.

Минимально поддержать:

### Images

-   `.jpg`
-   `.jpeg`
-   `.png`
-   `.webp`
-   `.gif`

### Video

-   `.mp4`
-   `.webm`
-   `.mov`
-   `.mkv`

Список расширений должен находиться в одном месте в коде и легко
расширяться.

Файлы и папки внутри `.library/` не считаются ассетами.

------------------------------------------------------------------------

## 4. Sidecar metadata

Метаданные ассета хранятся рядом с ним.

``` text
image01.jpg
image01.jpg.meta.json

video01.mp4
video01.mp4.meta.json
```

### Минимальный формат

``` json
{
  "version": 1,
  "id": "c0d76d39-07b7-45e4-a638-c642251fbb1d",
  "tags": [
    "female",
    "blonde",
    "two-participants"
  ]
}
```

### Поля

`version` --- версия формата metadata.

`id` --- постоянный UUID ассета.

`tags` --- список ID тегов.

На первой версии не нужно добавлять поля, которые пока не используются.

------------------------------------------------------------------------

## 5. Ассеты без metadata

Это основной сценарий первого запуска, потому что текущая библиотека уже
содержит файлы.

Если:

``` text
image01.jpg
```

существует, а:

``` text
image01.jpg.meta.json
```

отсутствует, приложение всё равно показывает ассет в библиотеке.

Такой ассет считается **Untagged**.

Не нужно создавать `.meta.json` для всех найденных файлов во время
сканирования.

Sidecar создаётся лениво --- при первом изменении метаданных ассета,
например при назначении первого тега.

При создании sidecar приложение генерирует UUID.

Это позволяет подключить существующую библиотеку без массового изменения
Google Drive.

------------------------------------------------------------------------

## 6. Глобальные данные Library

В корне библиотеки находится:

``` text
.library/
```

### `.library/config.json`

Минимально:

``` json
{
  "version": 1,
  "name": "Animation References"
}
```

### `.library/tags.json`

Теги являются глобальными сущностями библиотеки.

Пример:

``` json
{
  "version": 1,
  "groups": [
    {
      "id": "participants",
      "name": "Participants"
    },
    {
      "id": "gender",
      "name": "Gender"
    },
    {
      "id": "hair",
      "name": "Hair"
    },
    {
      "id": "franchise",
      "name": "Franchise"
    }
  ],
  "tags": [
    {
      "id": "female",
      "name": "Female",
      "groups": ["gender"]
    },
    {
      "id": "blonde",
      "name": "Blonde",
      "groups": ["hair"]
    },
    {
      "id": "two-participants",
      "name": "2",
      "groups": ["participants"]
    }
  ]
}
```

Связь `Tag -> Groups` --- many-to-many.

Один тег может принадлежать нескольким группам.

Ассеты ссылаются только на `tag.id`.

------------------------------------------------------------------------

## 7. Инициализация существующей папки

Если пользователь выбирает папку, в которой нет `.library/`, приложение
предлагает инициализировать её как Library.

Инициализация создаёт только:

``` text
.library/
├── config.json
└── tags.json
```

Существующие media-файлы не перемещаются и не переименовываются.

Sidecar-файлы для них автоматически не создаются.

------------------------------------------------------------------------

## 8. Сканирование

При открытии Library backend:

1.  читает `.library/config.json`;
2.  читает `.library/tags.json`;
3.  рекурсивно обходит Library;
4.  находит поддерживаемые media-файлы;
5.  проверяет наличие соответствующего `.meta.json`;
6.  читает metadata, если она существует;
7.  формирует в памяти текущий индекс ассетов;
8.  передаёт данные frontend.

В первой версии **индекс существует только в памяти процесса**.

После перезапуска приложения Library сканируется заново.

Это намеренное ограничение v1.

------------------------------------------------------------------------

## 9. Ошибки metadata

Некорректный `.meta.json` не должен ломать загрузку всей библиотеки.

Ассет отображается, но получает состояние ошибки.

Минимально различать:

-   invalid JSON;
-   unsupported metadata version;
-   duplicate UUID;
-   unknown tag ID;
-   sidecar без соответствующего media-файла.

Ошибки должны быть видны пользователю.

Приложение не должно автоматически удалять или исправлять данные без
явного действия пользователя.

------------------------------------------------------------------------

## 10. Browser UI

Основной экран --- визуальная галерея.

### Layout

``` text
┌──────────────────────────────────────────────────────┐
│ Search                                  Library name │
├───────────────┬──────────────────────────┬───────────┤
│ Filters       │                          │ Metadata  │
│               │      Asset Gallery       │           │
│ Participants  │                          │ Preview   │
│ Gender        │                          │ Tags      │
│ Hair          │                          │           │
│ Franchise     │                          │           │
│               │                          │           │
│ Untagged      │                          │           │
└───────────────┴──────────────────────────┴───────────┘
```

### Gallery

Для каждого ассета показывать:

-   preview;
-   image/video indicator;
-   выбранное состояние;
-   состояние metadata error, если оно есть.

По клику ассет выбирается.

### Preview

Изображение открывается в увеличенном виде.

Видео должно воспроизводиться в браузере, если формат поддерживается
браузером.

Для неподдерживаемого browser playback формата на первой версии
допустимо показать thumbnail/placeholder и путь к исходному файлу.

------------------------------------------------------------------------

## 11. Tagging

Для выбранного ассета справа показывается список назначенных тегов.

Пользователь может:

-   добавить существующий тег;
-   удалить тег;
-   создать новый тег;
-   создать новую группу;
-   назначить тег одной или нескольким группам.

После изменения ассета его sidecar записывается сразу.

После изменения структуры тегов сразу записывается `.library/tags.json`.

Не требуется отдельная кнопка Save.

Запись JSON должна быть атомарной:

1.  записать временный файл;
2.  успешно завершить запись;
3.  заменить оригинальный файл.

Это уменьшает вероятность повреждения metadata при аварийном завершении
приложения.

------------------------------------------------------------------------

## 12. Фильтрация

Минимальная фильтрация строится полностью по индексу в памяти.

Слева показываются группы тегов и их теги.

Нужно поддержать выбор нескольких тегов.

Для первой версии достаточно:

-   AND между выбранными тегами;
-   очистить все фильтры;
-   специальный фильтр `Untagged`.

Например:

``` text
Female
AND
Blonde
AND
2 participants
```

показывает только ассеты, содержащие все три тега.

OR и сложные логические выражения отложить.

------------------------------------------------------------------------

## 13. Untagged Inbox

Это обязательная часть первой версии.

Фильтр `Untagged` показывает все найденные media-файлы, у которых:

-   отсутствует sidecar; или
-   `tags` пустой.

Основной workflow добавления существующей библиотеки:

``` text
Open Library
    ↓
Untagged
    ↓
Select asset
    ↓
Assign tags
    ↓
Next asset
```

Желательно предусмотреть быстрый переход к следующему ассету после
разметки.

------------------------------------------------------------------------

## 14. Thumbnail

Для изображений браузер может первоначально использовать сам исходный
файл.

Для видео желательно генерировать thumbnail через `ffmpeg`.

Производные thumbnails **не должны храниться рядом с ассетами**.

Они относятся к локальному cache приложения.

Например:

``` text
%LOCALAPPDATA%/ReferenceLibrary/
└── cache/
    └── <library-id>/
        └── thumbnails/
```

Удаление cache не должно приводить к потере пользовательских данных.

Если генерация video thumbnails заметно увеличивает объём первой
итерации, допустимо временно использовать video placeholder.

------------------------------------------------------------------------

## 15. Backend

Рекомендуемый стек:

-   Python;
-   FastAPI;
-   `uvicorn`;
-   стандартная работа с JSON/filesystem;
-   `ffmpeg` для видео.

Backend отвечает за:

-   выбор/открытие Library;
-   сканирование filesystem;
-   чтение metadata;
-   запись metadata;
-   чтение/запись tags;
-   выдачу списка ассетов;
-   отдачу media frontend;
-   фильтрацию или передачу данных для client-side фильтрации;
-   генерацию thumbnails.

На первой версии при разумном размере библиотеки можно передавать индекс
frontend и фильтровать на клиенте.

------------------------------------------------------------------------

## 16. Frontend

Рекомендуемый стек:

-   React;

Основные компоненты:

App

## 17. Минимальный API

Точные URL не являются обязательным контрактом, но v1 потребуется
примерно следующий набор операций:

``` text
GET    /api/library
GET    /api/assets
GET    /api/assets/{id}

PUT    /api/assets/{id}/tags

GET    /api/tags
POST   /api/tags
PUT    /api/tags/{id}

POST   /api/tag-groups
PUT    /api/tag-groups/{id}

GET    /media/...
GET    /thumbnails/...
```

Filesystem path не должен использоваться frontend как идентификатор
ассета после того, как у ассета появился UUID.

Для ассета без sidecar backend может использовать временный runtime ID
до первого изменения.

------------------------------------------------------------------------

## 18. Что намеренно НЕ делаем в первой версии

Не включать в MVP:

-   SQLite;
-   полнотекстовый поисковый индекс;
-   Google Drive API;
-   собственную синхронизацию;
-   автоматическое разрешение sync conflicts;
-   несколько одновременно открытых Library;
-   batch tagging;
-   drag & drop import;
-   загрузку файлов по URL;
-   source URL;
-   notes;
-   rating/favorites;
-   saved searches;
-   OR-фильтры;
-   сложные boolean queries;
-   hierarchical tags;
-   автоматическое распознавание содержимого;
-   duplicate detection;
-   переименование и перемещение media через приложение;
-   автоматическое восстановление связи после ручного rename;
-   video contact sheets;
-   транскодирование видео;
-   редактирование самих media.

Google Drive в v1 рассматривается просто как внешний механизм
синхронизации папки Library.

------------------------------------------------------------------------

## 19. Порядок реализации

### Этап 1 --- Library reader

Сделать backend, который принимает путь к существующей Library и
рекурсивно находит media.

Результат: можно получить список всех существующих референсов.

### Этап 2 --- Metadata reader

Добавить `.meta.json` и `.library/tags.json`.

Результат: backend понимает размеченные и неразмеченные ассеты.

### Этап 3 --- Gallery

Сделать browser UI с grid существующих изображений и видео.

Результат: библиотеку уже можно использовать как визуальный каталог.

### Этап 4 --- Asset viewer

Выбор ассета, крупный preview, video playback.

### Этап 5 --- Tag editor

Добавление/удаление тегов и запись sidecar.

Результат: приложение начинает изменять Library.

### Этап 6 --- Groups and filters

Показ групп, AND-фильтрация, Untagged.

Результат: решена основная задача поиска референсов.

### Этап 7 --- Tag management

Создание и редактирование тегов/групп через UI.

### Этап 8 --- Video thumbnails и polish

Добавить thumbnails, обработку ошибок, loading states и основные
keyboard shortcuts.

------------------------------------------------------------------------

## 20. Критерий готовности v1

Первая версия считается готовой, если можно взять текущую папку с
референсами и без ручной миграции:

1.  подключить её как Library;
2.  увидеть все поддерживаемые изображения и видео;
3.  открыть любой референс;
4.  увидеть список неразмеченных файлов;
5.  создать группы и теги;
6.  назначить несколько тегов референсу;
7.  перезапустить приложение и не потерять разметку;
8.  выбрать несколько тегов и получить подходящие референсы;
9.  изменить файлы в Library вне приложения и после повторного
    сканирования увидеть актуальное состояние;
10. удалить локальное приложение/cache и затем восстановить весь каталог
    только из папки Library.

Последний пункт является главным архитектурным тестом:

> **Если сохранилась Library, никакие пользовательские данные не
> потеряны.**
